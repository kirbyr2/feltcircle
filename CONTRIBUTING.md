# Contributing to FeltCircle

Thanks for helping! Bug reports, translations and pull requests are welcome.

## Setup

```bash
npm install          # Node.js 22.13+ required
npm run dev:server   # backend on :8787
npm run dev          # web app with hot reload
```

Before opening a pull request, run:

```bash
npm run check        # typecheck + tests + build
```

UI component tests use React Testing Library with jsdom (`apps/web/test/*.test.tsx`); put `// @vitest-environment jsdom` at the top of new UI test files. The browser end-to-end tests (`tests/e2e.test.ts`, Playwright with a local Chrome) run when a built web app (`npm run build:web`) and a local Chrome/Chromium are present. Set `CHROME_PATH` if your browser is somewhere unusual, `E2E_SHOTS=<dir>` to save screenshots, or `SKIP_E2E=1` to skip them.

## Ground rules

- **Rules live in `packages/poker-engine`.** It is pure and deterministic: no timers, no I/O, no randomness. Any rule change needs a test in `packages/poker-engine/test`. Chip conservation (`totalChips` never changes) must always hold.
- **Room behaviour lives in `packages/room-core`,** shared by Local Mode, the Node.js server and Cloudflare. Don't fork logic into a backend. `tests/consistency.test.ts` replays the same script on all three and requires identical results.
- **Clients never decide outcomes.** Online, the server validates every command. The web app only renders `RoomView`s and sends commands.
- **Protocol changes:** bump `PROTOCOL_VERSION` in `packages/game-protocol` when a change is not backward compatible. Old clients then get a clear "please reload" message.
- **Persisted state changes:** `RoomState.schema` and the SQLite migrations in `apps/server-node/src/db.ts` must keep existing rooms loadable. Add a new migration and never edit an old one.
- **No hard-coded domains, secrets, analytics or required external services.**
- **No real-money features, virtual cards or hand evaluation.** These are out of scope by design. The Hand Rankings guide is static reference text.
- **New games** are added to `GAME_CATALOG` in `packages/game-protocol` (shared by the UI and both backends). Keep `available: false` until the game is fully implemented; backends reject unavailable games.
- **Sounds** are generated by `npm run sounds -w @feltcircle/web` (`apps/web/scripts/make-sounds.mjs`). Only add audio you created or that has a compatible license, and play sounds only from confirmed state changes (`lib/sound-events.ts`).
- **The Node server deliberately uses plain `node:http` + `ws`,** with no web framework. It has only a handful of routes, and keeping dependencies minimal keeps the single-file bundle small and easy to audit.

## Translations

Locale files are in `packages/i18n/locales/<code>.json`, and English (`en.json`) is the source of truth. A test enforces that:

- every locale has exactly the same keys as `en.json`,
- `{placeholders}` match,
- every `t('key')` used in the web app exists.

To fix a translation, edit the JSON. To add a language, add the file, register it in `packages/i18n/src/index.ts`, and add it to `LANGUAGES` in `packages/game-protocol`. Keep poker terms the way players at a real table say them in that language.

## Commit style

Small, focused commits with a clear message. Please describe how you tested the change in the pull request.
